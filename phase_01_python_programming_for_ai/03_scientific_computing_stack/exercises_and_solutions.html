Practice problem set covering stride offsets, SIMD vectorization speedup, and DataFrame indexing.

Problem 1: Hand-Calculating Stride Offsets and Zero-Copy Transposition

Medium

Consider a 2D matrix $A$ of shape $(3, 4)$ stored in row-major order with strides $(4, 1)$. Compute the flat index for $A[2, 3]$ and show how transposing into $A^T$ with shape $(4, 3)$ and strides $(1, 4)$ accesses the exact same memory in $\mathcal{O}(1)$ time.

Click to view solution for Problem 1
$$\text{flat\_index}_A(2, 3) = (2 \times 4) + (3 \times 1) = 8 + 3 = \mathbf{11}$$

After swapping shapes and strides to $(4, 3)$ and $(1, 4)$:

$$\text{flat\_index}_{A^T}(3, 2) = (3 \times 1) + (2 \times 4) = 3 + 8 = \mathbf{11}$$

Both map directly to flat element index 11 with zero memory copies!

Problem 2: Vectorization vs. Loop Asymptotics

Medium

A pure Python loop takes $42\text{ ns}$ per element on $10,000,000$ numbers ($0.42\text{ s}$). A SIMD instruction processes 16 floats per clock cycle ($0.156\text{ ms}$). Calculate the speedup factor.

Click to view solution for Problem 2
$$\text{Speedup} = \frac{0.42\text{ s}}{0.00015625\text{ s}} \approx \mathbf{2,688\times\text{ faster!}}$$

Problem 3: DataFrame Indexing Precision (.loc vs. .iloc)

Challenging

Given index labels `['epoch_3', 'epoch_1', 'epoch_2']` with columns `['loss', 'accuracy']`, explain the difference between df.loc['epoch_1', 'loss'] and df.iloc[1, 0].

Click to view solution for Problem 3

Both return 0.92! .loc finds the row by its text name 'epoch_1', whereas .iloc counts 0-indexed integer position down to physical row 1.
