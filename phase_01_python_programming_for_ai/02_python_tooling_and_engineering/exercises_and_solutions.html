Problem 1: Unit Testing Numerical Invariants & Safe Softmax

Medium

In standard floating-point arithmetic, computing $e^{z_i}$ for $z_i \ge 710$ raises an OverflowError or produces nan.

  1. Implement safe_softmax(logits) using the max-subtraction stabilization technique.
  2. Write a unittest.TestCase checking:
    • Probabilities sum to $1.0$ within tolerance.
    • No nan or overflow occurs when tested with [1000.0, 1001.0, 1002.0].
Click to Reveal Step-by-Step Solution 
import math
import unittest

def safe_softmax(logits: list[float]) -> list[float]:
    if not logits:
        return []
    max_val = max(logits)
    # Subtract max_val to prevent overflow
    exps = [math.exp(x - max_val) for x in logits]
    sum_exps = sum(exps)
    return [e / sum_exps for e in exps]

class TestSoftmax(unittest.TestCase):
    def test_sum_to_one(self):
        probs = safe_softmax([1.0, 2.0, 3.0])
        self.assertAlmostEqual(sum(probs), 1.0, places=6)

    def test_overflow_protection(self):
        probs = safe_softmax([1000.0, 1001.0, 1002.0])
        self.assertFalse(any(math.isnan(p) for p in probs))
        self.assertAlmostEqual(sum(probs), 1.0, places=6)

Problem 2: Algorithmic Profiling & Eliminating Bottlenecks

Medium

Consider an unoptimized vocabulary filter scanning $N = 100{,}000$ tokens against a stopword list of $M = 5{,}000$ items using a Python list: token not in stopwords.

  1. What is the Big-O time complexity?
  2. How can the data structure be altered to reduce lookup complexity to $O(1)$?
  3. Why does this CPU bottleneck cause GPU starvation during deep learning training?
Click to Reveal Step-by-Step Solution
1. Complexity: Scanning an $M$-element list for $N$ tokens is $O(N \times M)$ ($500{,}000{,}000$ comparisons).
2. Optimization: Convert the stopword collection into a set (hash table). Set lookups are $O(1)$ on average, reducing total runtime to $O(N + M)$—yielding a ~9,000x speedup!
3. GPU Starvation: Deep learning accelerators (GPUs) compute batches in milliseconds. If the CPU host thread takes tens of seconds preparing the next batch, the GPU remains idle at 0% utilization.

Problem 3: Production Training Configuration & Reproducibility Harness

Challenging

Implement an ExperimentConfig dataclass that manages hyperparameters, locks pseudo-random seeds, and ensures that separate script executions produce identical stochastic weight draws.

Click to Reveal Step-by-Step Solution 
import random
from dataclasses import dataclass

@dataclass
class ExperimentConfig:
    seed: int
    learning_rate: float
    batch_size: int

    def lock_seeds(self):
        random.seed(self.seed)

# Verification
cfg1 = ExperimentConfig(seed=42, learning_rate=1e-4, batch_size=32)
cfg2 = ExperimentConfig(seed=42, learning_rate=1e-4, batch_size=32)

cfg1.lock_seeds()
draws1 = [random.random() for _ in range(3)]

cfg2.lock_seeds()
draws2 = [random.random() for _ in range(3)]

assert draws1 == draws2
print("Deterministic reproducibility confirmed!")
