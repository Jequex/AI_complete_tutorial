Problem 1: Memory Mutability, Reference Aliasing & Default Arguments

Medium

In AI training scripts, bugs often arise from unintended reference aliasing or default mutable arguments accumulating state across epochs.

Part A: Predict the Output

def train_model(epoch_data, training_history=[]):
    training_history.append(epoch_data)
    return training_history

run_1 = train_model("loss: 0.85")
print("Run 1:", run_1)

run_2 = train_model("loss: 0.62")
print("Run 2:", run_2)

print("run_1 is run_2:", run_1 is run_2)

Part B: The Shallow Multiplication Trap

row = [0.0, 0.0, 0.0]
matrix = [row] * 3
matrix[0][1] = 5.0
print("Matrix:", matrix)
Click to view solution for Problem 1

Part A Solution:

Run 1 Output: ['loss: 0.85']

Run 2 Output: ['loss: 0.85', 'loss: 0.62']

Identity Check: True

Explanation: Default arguments are evaluated only once at function definition time. run_1 and run_2 point to the exact same list in memory.

# Fixed Implementation
def train_model(epoch_data, training_history=None):
    if training_history is None:
        training_history = []
    training_history.append(epoch_data)
    return training_history

Part B Solution:

Output: [[0.0, 5.0, 0.0], [0.0, 5.0, 0.0], [0.0, 5.0, 0.0]]

Explanation: [row] * 3 copies the pointer, not the list. Modifying one row changes all three rows.

# Correct Independent Rows
matrix = [[0.0 for _ in range(3)] for _ in range(3)]
matrix[0][1] = 5.0

Problem 2: Hand Calculation of a Linear Layer Forward Pass

Medium

Given the forward equation $\mathbf{y} = \mathbf{W}\mathbf{x} + \mathbf{b}$ with parameters:

$$\mathbf{W} = \begin{bmatrix} 2.0 & -1.0 \\ 0.5 & 3.0 \end{bmatrix}, \qquad \mathbf{x} = \begin{bmatrix} 4.0 \\ 1.0 \end{bmatrix}, \qquad \mathbf{b} = \begin{bmatrix} 0.5 \\ -2.0 \end{bmatrix}$$

Calculate neurons $y_1$ and $y_2$ step-by-step.

Click to view solution for Problem 2

Step 1: Neuron 1 ($y_1$)

$$y_1 = (2.0 \times 4.0) + (-1.0 \times 1.0) + 0.5 = 8.0 - 1.0 + 0.5 = \mathbf{7.5}$$

Step 2: Neuron 2 ($y_2$)

$$y_2 = (0.5 \times 4.0) + (3.0 \times 1.0) + (-2.0) = 2.0 + 3.0 - 2.0 = \mathbf{3.0}$$

Step 3: Final Output Vector

$$\mathbf{y} = \begin{bmatrix} 7.5 \\ 3.0 \end{bmatrix}$$

Problem 3: Lazy Batch Streamer & Memory Complexity

Challenging

You train on an image dataset of $N = 100,000$ images, each taking $2\text{ MB}$ of memory.

  1. If loaded eagerly into a Python list, how many GB of RAM is required?
  2. If streamed using a generator with batch size $B = 32$, how many MB of RAM is required?
  3. State the asymptotic memory complexity ($\mathcal{O}(\cdot)$) of each approach.
Click to view solution for Problem 3

Step 1: Eager List

$$\text{Total Memory} = 100,000 \times 2\text{ MB} = 200,000\text{ MB} \approx \mathbf{195.31\text{ GB of RAM}}$$

Step 2: Generator Streamer

$$\text{Active Memory} = 32 \times 2\text{ MB} = \mathbf{64\text{ MB of RAM}}$$

Step 3: Big-O Complexity

  • Eager List: $\mathcal{O}(N)$ (grows linearly with total dataset size).
  • Generator Streamer: $\mathcal{O}(B) = \mathcal{O}(1)$ with respect to dataset size $N$.
