Topic 13.2: Object-Oriented Deep Learning — Modules, Optimizers & Loops

Mastering PyTorch's architectural patterns: `nn.Module` tree traversal, `Parameter` vs `register_buffer`, modular `Dataset`/`DataLoader` pipelines, and the standard 5-step training loop.

1. Executive Summary & The 12-Year-Old Analogy

Building neural networks requires managing hundreds of millions of parameters, caching activations, executing complex gradient updates, and streaming terabytes of data. PyTorch solves this through object-oriented abstractions centered around nn.Module and DataLoader.

The 12-Year-Old Analogy: The Model Assembly Line & Training Coach

Think of a futuristic racecar assembly plant.

An nn.Module is a sub-assembly like the engine or transmission. Inside the engine are tuning screws called nn.Parameter. When you turn a screw, the engine's performance changes.

The car also has a dashboard odometer called a buffer (register_buffer). It tracks total miles driven (step_count). You don't tune the odometer to make the car faster, but you must record it when saving the car to the garage!

The Dataset is the parts warehouse where every crate has a barcode (__getitem__). The DataLoader is the forklift driver that grabs 32 random crates at a time (batch_size), shuffles them so workers don't repeat patterns (shuffle=True), and delivers them to the line.

Finally, the Coach (Optimizer) runs the 5-step drill: Wipe the telemetry board (zero_grad()) $\to$ Test lap (forward()) $\to$ Calculate time deficit (loss()) $\to$ Compute exact screw adjustments (backward()) $\to$ Turn the wrenches (optimizer.step())!

3. The Canonical 5-Step Training Loop

Every training step in standard PyTorch pipelines follows this immutable protocol:

for epoch in range(num_epochs):
    model.train()  # 1. Enable training mode (Dropout & BatchNorm active)
    for batch_x, batch_y in dataloader:
        optimizer.zero_grad()               # 1. Reset accumulated gradients
        outputs = model(batch_x)            # 2. Forward pass (builds dynamic DAG)
        loss = criterion(outputs, batch_y)  # 3. Compute scalar loss
        loss.backward()                     # 4. Reverse-mode autograd (.grad populated)
        optimizer.step()                    # 5. Update weights using gradients

Why optimizer.zero_grad() is Mandatory

Because PyTorch accumulates gradients via addition (param.grad += upstream_grad), failing to call zero_grad() causes gradients from successive batches to sum indefinitely, leading to immediate gradient explosion and diverging weights!

4. Checkpointing: Saving State Dictionaries

Always save models using state_dict rather than pickling the full Python object. This prevents dangerous arbitrary code execution vulnerabilities and cross-version deserialization crashes: 

# Checkpoint saving
torch.save({
    'epoch': epoch,
    'model_state_dict': model.state_dict(),
    'optimizer_state_dict': optimizer.state_dict(),
}, 'checkpoint.pt')

# Safe checkpoint restoration
checkpoint = torch.load('checkpoint.pt', weights_only=True)
model.load_state_dict(checkpoint['model_state_dict'])
