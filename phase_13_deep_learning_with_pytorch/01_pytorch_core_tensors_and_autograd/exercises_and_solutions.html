Problem 1: Memory Address Mapping in 4D Vision Tensors (NCHW to NHWC)

Consider an input image batch tensor with shape $(N=4, C=3, H=32, W=32)$.

  1. Derive the canonical C-contiguous strides vector $\mathbf{s}_{\text{NCHW}}$.
  2. Compute the exact physical 1D storage index for element $(n=2, c=1, h=10, w=15)$ assuming storage_offset = 0.
  3. If the tensor is permuted via x.permute(0, 2, 3, 1) to $(N, H, W, C)$:
    • What are the resulting shape and strides?
    • Is this permuted tensor contiguous? Why or why not?
    • What is the physical storage index of element $(n=2, h=10, w=15, c=1)$ in the permuted tensor?

Solution 1

1. Stride Derivation:

$$s_3 = 1, \quad s_2 = 1 \cdot 32 = 32, \quad s_1 = 32 \cdot 32 = 1024, \quad s_0 = 1024 \cdot 3 = 3072$$ $$\mathbf{s}_{\text{NCHW}} = (3072, 1024, 32, 1)$$

2. Storage Address:

$$\text{addr} = 2(3072) + 1(1024) + 10(32) + 15(1) = 6144 + 1024 + 320 + 15 = 7503$$

3. Permuted View:

Shape: $(4, 32, 32, 3)$. Strides: $(3072, 32, 1, 1024)$. Non-contiguous because canonical row-major strides would be $(3072, 96, 3, 1)$. Re-evaluating the physical index yields $2(3072) + 10(32) + 15(1) + 1(1024) = 7503$, confirming zero-copy memory re-indexing!

Problem 2: Reverse-Mode Autograd with Diamond Graph Recombination

Let $x = 2.0$, and define intermediate variables: $$u = x^2, \quad v = 3x, \quad y = u \cdot v + u$$

  1. Compute the analytical derivative $\frac{dy}{dx}$ at $x=2.0$.
  2. Trace the reverse-mode autograd accumulation at nodes $u$ and $x$.

Solution 2

Analytical Derivation:

$$y = 3x^3 + x^2 \implies \frac{dy}{dx} = 9x^2 + 2x \implies 9(4) + 2(2) = 40.0$$

Autograd Backpropagation:

At root $y$: $\bar{y} = 1.0$. Gradients flowing into $u$ come from both $u \cdot v$ and $+u$: $\bar{u} = \bar{y} \cdot v + \bar{y} \cdot 1.0 = 1.0(6.0) + 1.0(1.0) = 7.0$.

Gradients flowing into $x$: from $v$: $\bar{v} \cdot 3 = 4.0(3) = 12.0$; from $u$: $\bar{u} \cdot 2x = 7.0(4.0) = 28.0$. Total accumulated gradient at $x$: $12.0 + 28.0 = 40.0$.

Problem 3: Diagnosing Memory Leaks in PyTorch Training/Eval Loops

Why does appending losses.append(loss) inside an evaluation loop cause a CUDA Out of Memory crash, and how is it resolved?

Solution 3

The loss tensor retains a reference to its .grad_fn and the entire dynamic backward graph (including cached activations). Appending tensors directly keeps all prior graph nodes alive in RAM.

Fix: Use losses.append(loss.item()) to store pure Python floats, and wrap inference in with torch.inference_mode(): or with torch.no_grad():.
