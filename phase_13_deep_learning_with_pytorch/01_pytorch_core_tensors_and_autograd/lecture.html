Topic 13.1: PyTorch Core — Tensors, Strides & Dynamic Autograd

Demystifying PyTorch tensor internals: physical storage buffers, strides, zero-copy views, non-contiguous operations, and reverse-mode automatic differentiation DAGs.

1. Executive Summary & The 12-Year-Old Analogy

PyTorch unites high-performance hardware-accelerated multidimensional array math with dynamic automatic differentiation. Rather than storing numbers in multi-layered arrays, PyTorch separates physical memory (a 1D flat buffer called Storage) from logical views defined by shape, strides, and storage_offset.

The 12-Year-Old Analogy: The Digital Lego Engine & Memory Blueprint

Imagine a giant organizer box filled with 1,000 numbered slots in a single straight row ($0$ to $999$). This is your Storage.

A Tensor is a magic blueprint lens that looks at this straight row. It tells your eyes: "Treat this as a 2×3 table! To jump to the next row, skip forward 3 slots in the box (stride=3); to jump to the next column, step forward 1 slot (stride=1)."

When you transpose the table, you don't move the heavy plastic blocks. You merely tweak the instruction lens: "To go to the next row, jump 1 slot; to go to the next column, jump 3 slots!" It happens at the speed of light with zero memory duplication.

Meanwhile, the Autograd Engine is an automated camera recorder running during your robot's assembly. When you tell it to run backwards (.backward()), it traces each gear in reverse order and calculates precisely which gear needs adjustment to make the robot faster!

2. Mathematical Symbol Decoder

Symbol Mathematical Domain Description & Engineering Interpretation
$\mathcal{S}$ 1D Memory Buffer Raw contiguous 1D array of physical memory elements (like C++ THStorage).
$\mathbf{d} = (d_0, \dots, d_{D-1})$ $\mathbb{N}^D$ Logical shape tuple specifying the dimensionality of the tensor.
$\mathbf{s} = (s_0, \dots, s_{D-1})$ $\mathbb{N}^D$ Strides vector: memory steps required to advance by 1 unit along axis $k$.
$\Delta$ $\mathbb{N}$ Storage offset: index in $\mathcal{S}$ representing coordinate $(0, \dots, 0)$.
$\text{coord}(\mathbf{i})$ Indexing Formula Memory mapping: $\text{addr} = \Delta + \sum_{k=0}^{D-1} i_k s_k$.
$\mathcal{G} = (\mathcal{V}, \mathcal{E})$ Directed Acyclic Graph Dynamic DAG of mathematical operators and tensors constructed during forward execution.
$\text{grad\_fn}$ Function Object Internal pointer to backward derivative evaluation function (e.g. AddBackward0).

3. Physical Storage, Strides & Contiguity

In C-contiguous (row-major) order, strides are defined by the cumulative products of following dimensions:

$$s_k = \prod_{j=k+1}^{D-1} d_j, \quad \text{with } s_{D-1} = 1$$

Consider a $(2, 3)$ matrix. The elements are laid out linearly in RAM: 

Storage: [ 10.0, 20.0, 30.0, 40.0, 50.0, 60.0 ]
Shape:   (2, 3)
Strides: (3, 1)

The Non-Contiguous Trap: Why .view() Fails

When you transpose this matrix via tensor.t(), PyTorch simply sets shape to $(3, 2)$ and strides to $(1, 3)$. The memory is completely unchanged!

However, consecutive logical elements along a row now require jumping 3 slots in RAM rather than 1. Because the memory is non-contiguous, calling .view(...) fails with a RuntimeError. To fix this, call .contiguous() to allocate a freshly aligned buffer, or use .reshape(...).

4. Dynamic Autograd & Reverse-Mode Differentiation

PyTorch uses a Define-by-Run tape-based dynamic graph. As mathematical operators execute on tensors with requires_grad=True, PyTorch dynamically creates backward nodes. 

import torch

x = torch.tensor(3.0, requires_grad=True)
y = torch.tensor(4.0, requires_grad=True)

# Forward pass builds computational DAG dynamically:
f = (x * y) + (y ** 2)

# Reverse-mode autograd:
f.backward()

print("df/dx:", x.grad)  # 4.0 (y)
print("df/dy:", y.grad)  # 11.0 (x + 2*y)

Best Practice: Inference Mode with torch.no_grad()

During evaluation or inference, wrap forward passes in with torch.no_grad():. This disables DAG node instantiation and prevents activation caching, reducing memory consumption by over 50%.
