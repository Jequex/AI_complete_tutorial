Problem 1: Manual Prefix-Tuning Attention Allocation (Easy)

Given $\mathbf{q} = [1.0, 0.0]^T$, sequence key $\mathbf{k}_{\text{seq}} = [0.0, 1.0]^T$, prefix key $\mathbf{p}_K = [1.0, 1.0]^T$, prefix value $\mathbf{p}_V = [5.0, 5.0]^T$, and sequence value $\mathbf{v}_{\text{seq}} = [1.0, 0.0]^T$ with $d_k = 2$:

  1. Compute raw dot-product scores for prefix key and sequence key.
  2. Compute scaled logits $z = \mathbf{q}^T \mathbf{k} / \sqrt{2}$.
  3. Compute softmax probabilities and contextual output $\mathbf{h}$.
View Complete Solution

Calculations:

$$\mathbf{q} \cdot \mathbf{p}_K = 1.0, \quad \mathbf{q} \cdot \mathbf{k}_{\text{seq}} = 0.0$$ $$z_{\text{prefix}} = \frac{1}{\sqrt{2}} \approx 0.7071, \quad z_{\text{seq}} = 0.0$$ $$a_{\text{prefix}} = \frac{e^{0.7071}}{e^{0.7071} + 1.0} \approx \mathbf{66.98\%}, \quad a_{\text{seq}} \approx \mathbf{33.02\%}$$ $$\mathbf{h} = 0.6698 \begin{bmatrix} 5.0 \\ 5.0 \end{bmatrix} + 0.3302 \begin{bmatrix} 1.0 \\ 0.0 \end{bmatrix} = \begin{bmatrix} \mathbf{3.6792} \\ \mathbf{3.3490} \end{bmatrix}$$

The learnable prefix captures two-thirds of the attention mass, steering the output vector without modifying sequence weights.

Problem 2: Context Budget & FLOPs Penalty of Prompt Tuning vs. LoRA (Hard)

Compare LoRA (which merges weights and adds $0$ virtual tokens) with Prompt Tuning ($L_p = 64$ virtual tokens) for sequence length $T = 2048$ with $T_{\max} = 2048$:

  1. Compute the quadratic attention FLOPs increase $((T + L_p)/T)^2$.
  2. For an input query of 2000 tokens, determine available generation room under LoRA vs. Prompt Tuning.
View Complete Solution

1. FLOPs Increase:

$$\text{Ratio} = \left(\frac{2112}{2048}\right)^2 \approx (1.03125)^2 \approx 1.0635 \implies \mathbf{+6.35\% \text{ FLOPs increase across every layer}}.$$

2. Generation Budget:

  • LoRA: $2048 - 2000 = \mathbf{48 \text{ tokens}}$ of response generation.
  • Prompt Tuning: $2048 - (2000 + 64) = \mathbf{-16 \text{ tokens (Context Overflow Error!)}}$.

Prompt tuning imposes a permanent runtime context length tax on every single inference request, whereas LoRA leaves the context window completely untouched.
