Topic 28.1: GPU Architecture, CUDA & Memory Hierarchy

A rigorous examination of high-performance computing for deep learning: from Streaming Multiprocessors and Warp SIMT lockstep execution to Tensor Cores, memory tiers, and the Roofline Model.

12-Year-Old Intuition: The Racecar vs. The Freight Train

Imagine moving 1,000 heavy cargo boxes across town:

  • The Ferrari (CPU): Carries only one box at a time, but speeds at 200 mph with laser-sharp steering, completing a run in 2 minutes. For unpredictable, sequential errands, it's supreme. But moving 1,000 boxes takes 2,000 minutes (over 33 hours!).
  • The Freight Train (GPU): Moves at a modest 25 mph, cannot make sudden turns, and takes time to get rolling. But it has 1,000 flatbed cars attached side-by-side. On a single trip, it hauls all 1,000 boxes at once in 30 minutes!

Deep learning is about performing billions of identical multiplications at once. The GPU abandons complex sequential steering logic to pack tens of thousands of floating-point arithmetic engines onto a single chip.

CPU vs. GPU Architectural Comparison

Latency-Optimized (CPU) vs. Throughput-Optimized (GPU)

A modern CPU dedicates over 50% of its die space to caching (L2, L3) and speculative instruction-level parallelism (branch predictors, reorder buffers). A modern GPU dedicates 80%+ of silicon area to raw Arithmetic Logic Units (ALUs).

When memory stalls occur ($300 - 800\text{ cycles}$ to fetch from HBM), the GPU does not wait: the warp scheduler instantly swaps in another ready warp in 1 clock cycle. Concurrency hides latency.

Streaming Multiprocessors, Warps, and SIMT Divergence

In CUDA, threads execute in lockstep groups of 32 known as Warps. When threads within a warp evaluate a conditional branch to different targets:

if (threadIdx.x < 16) {
    path_A(); // 40 cycles
} else {
    path_B(); // 40 cycles
}

The hardware must serialize execution: it executes Path A for threads 0–15 while masking off threads 16–31, then executes Path B for threads 16–31 while masking off threads 0–15.

$$\text{Total Cycles} = 40 + 40 = 80\text{ cycles} \quad (50\%\text{ of compute capability wasted!})$$

Tensor Cores & Mixed-Precision MMA

Unlike standard CUDA cores that operate on scalars ($d = a \cdot b + c$), Tensor Cores execute hardware Matrix Multiply-Accumulate (MMA) operations per clock cycle:

$$\mathbf{D}_{\text{FP32}} = \mathbf{A}_{\text{FP16/BF16/FP8}} \times \mathbf{B}_{\text{FP16/BF16/FP8}} + \mathbf{C}_{\text{FP32}}$$

On an NVIDIA H100 SXM5:

  • Standard FP32 CUDA Cores: $\approx 67\text{ TFLOP/s}$
  • FP16/BF16 Tensor Cores: $\mathbf{989\text{ TFLOP/s}}$ ($>14\times$ faster)
  • FP8 Tensor Cores: $\mathbf{1{,}978\text{ TFLOP/s}}$ ($>29\times$ faster)

The GPU Memory Hierarchy

  • Registers: ~64 KB per SM ($>25\text{ TB/s}$ aggregate), 1 cycle latency.
  • Shared Memory / L1 Data Cache (SRAM): ~192–256 KB per SM ($15–19\text{ TB/s}$), ~20 cycles latency. Used by FlashAttention to tile Q, K, V matrices.
  • L2 Cache: Shared across all SMs (~50 MB on A100/H100, $5–7\text{ TB/s}$), ~100 cycles latency.
  • High Bandwidth Memory (HBM2e / HBM3): Off-chip VRAM (80GB–144GB, $2.0–3.35\text{ TB/s}$), $300–800\text{ cycles}$ latency.

Arithmetic Intensity & The Roofline Model

The operational intensity of any algorithm is defined as:

$$I = \frac{\text{Work (FLOPs)}}{\text{Memory Movement (Bytes)}} \quad \left[\frac{\text{FLOP}}{\text{Byte}}\right]$$

The attainable performance $P$ is bounded by:

$$P = \min\left(P_{\text{peak}}, \; I \cdot B_{\text{peak}}\right)$$

The Ridge Point $I^* = \frac{P_{\text{peak}}}{B_{\text{peak}}}$ marks the transition from memory-bandwidth limited to compute-limited performance:

  • NVIDIA A100: $I^* = \frac{312 \times 10^{12}}{2039 \times 10^9} \approx 153.0\text{ FLOP/Byte}$
  • NVIDIA H100: $I^* = \frac{989 \times 10^{12}}{3350 \times 10^9} \approx 295.2\text{ FLOP/Byte}$

Engineering Implication: Kernel Fusion

Because elementwise activations and normalizations have tiny arithmetic intensities ($I \le 2.5$), keeping them as separate PyTorch operations floods the slow HBM bus. Kernel Fusion (e.g. FlashAttention, PyTorch torch.compile, Triton) executes activation, normalization, and projection within on-chip SRAM, eliminating HBM round trips entirely.
