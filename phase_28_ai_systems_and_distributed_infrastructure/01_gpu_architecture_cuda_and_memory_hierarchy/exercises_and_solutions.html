Exercise 1: Arithmetic Intensity & Kernel Fusion of Softmax

Consider computing the Softmax function over a batch of vectors: $\mathbf{y} = \text{Softmax}(\mathbf{x})$, $\mathbf{x} \in \mathbb{R}^{B \times S}$ with $B = 32$, $S = 4{,}096$ in FP16 ($2\text{ bytes/element}$).

The numerically stable algorithm requires: (1) max reduction ($S$ ops), (2) sum of exp ($3S$ ops), (3) normalization ($3S$ ops) $\implies 7S\text{ FLOPs}$ per vector.

  1. Compute total FLOPs and memory traffic for a naive PyTorch implementation writing intermediates to HBM.
  2. Compute memory traffic for a fused kernel holding vectors in on-chip SRAM.
  3. Compute the Arithmetic Intensity $I$ for both. On NVIDIA A100 ($P_{\text{peak}} = 312\text{ TFLOP/s}$, $B_{\text{peak}} = 2{,}039\text{ GB/s}$, $I^* = 153.0\text{ FLOP/B}$), calculate the attainable performance and fusion speedup.
Click to view Solution

Solution:

1. Naive (Unfused) Implementation:

  • Total Elements: $N = 32 \times 4{,}096 = 131{,}072$.
  • Total FLOPs: $7 \times 131{,}072 = 917{,}504\text{ FLOPs} \approx 0.918\text{ MFLOPs}$.
  • Memory Traffic: Read $\mathbf{x}$ ($2N$), Read/Write intermediate numerators ($4N$), Write $\mathbf{y}$ ($2N$) plus initial reduction read ($2N$) $= 10N\text{ bytes} \approx 1.31\text{ MB}$.
  • $I_{\text{naive}} = \frac{7N}{20N} = \mathbf{0.35\text{ FLOPs/Byte}}$.

2. Fused Implementation:

  • Memory Traffic: Read $\mathbf{x}$ once ($2N$), write $\mathbf{y}$ once ($2N$) $= 4N\text{ bytes} \approx 0.524\text{ MB}$.
  • $I_{\text{fused}} = \frac{7N}{8N} = \mathbf{0.875\text{ FLOPs/Byte}}$.

3. Attainable Performance & Speedup (A100):

Both are deeply memory-bound since $I \ll 153.0\text{ FLOP/B}$.

$$P_{\text{naive}} = 0.35 \times 2{,}039\text{ GB/s} = 713.65\text{ GFLOP/s} = 0.714\text{ TFLOP/s} \quad (0.23\%\text{ of peak})$$

$$P_{\text{fused}} = 0.875 \times 2{,}039\text{ GB/s} = 1{,}784.1\text{ GFLOP/s} = 1.784\text{ TFLOP/s} \quad (0.57\%\text{ of peak})$$

Kernel fusion yields a $\frac{10N}{4N} = \mathbf{2.5\times}$ speedup purely by saving memory bandwidth.

Exercise 2: SIMT Warp Divergence Penalty Analysis

A warp of 32 threads executes the following branch:

if (threadIdx.x % 2 == 0) {
    path_even(); // 120 instructions
} else {
    path_odd();  // 80 instructions
}
  1. How many execution cycles does the warp require to complete?
  2. What is the active SIMT thread slot efficiency?
  3. How can the data mapping be refactored to eliminate divergence completely?
Click to view Solution

Solution:

1. Required Cycles:

Because adjacent threads alternate even and odd, each 32-thread warp contains 16 even threads and 16 odd threads. The SIMT scheduler serializes execution:

$$\text{Total Cycles} = 120 + 80 = \mathbf{200\text{ cycles}}$$

2. SIMT Slot Efficiency:

Useful work: $(16 \times 120) + (16 \times 80) = 1{,}920 + 1{,}280 = 3{,}200\text{ thread-instructions}$.

Total allocated slots: $32\text{ threads} \times 200\text{ cycles} = 6{,}400\text{ slot-cycles}$.

$$\text{Efficiency } \eta = \frac{3{,}200}{6{,}400} = \mathbf{50.0\%}$$

3. Refactoring:

Remap workloads so that all 32 threads within a single warp branch together: assign even workloads to warps $0, 2, 4\dots$ and odd workloads to warps $1, 3, 5\dots$. Even warps take 120 cycles ($100\%$ efficiency), odd warps take 80 cycles ($100\%$ efficiency), giving an average of 100 cycles ($2\times$ faster).

Exercise 3: Hardware Derivation of Tensor Core Peak Throughput

An NVIDIA H100 SXM5 GPU features 132 SMs running at a base clock of $1.83\text{ GHz}$. Each SM contains 4 Fourth-Generation Tensor Cores. Each Tensor Core executes a $16 \times 16 \times 16$ FP16 MMA matrix tile per cycle ($\mathbf{D} = \mathbf{A}\mathbf{B} + \mathbf{C}$).

  1. Derive the number of scalar FLOPs in one $16 \times 16 \times 16$ MMA operation.
  2. Calculate the theoretical peak FP16 Tensor Core throughput in TFLOP/s from first principles.
Click to view Solution

Solution:

1. FLOPs per MMA Tile:

Matrix $\mathbf{A} \in \mathbb{R}^{16 \times 16}$ multiplied by $\mathbf{B} \in \mathbb{R}^{16 \times 16}$ yields $16 \times 16 = 256$ elements. Each element requires a 16-element dot product (16 multiplies, 16 adds = 32 FLOPs).

$$\text{FLOPs per tile} = 2 \times 16 \times 16 \times 16 = \mathbf{8{,}192\text{ FLOPs}}$$

2. Peak TFLOP/s Derivation:

Total Tensor Cores: $132\text{ SMs} \times 4 = 528\text{ Tensor Cores}$.

FLOPs per cycle across chip: $528 \times 8{,}192 = 4{,}325{,}376\text{ FLOPs/cycle}$.

$$\text{Throughput} = 4{,}325{,}376 \times 1.83 \times 10^9\text{ cycles/s} \approx \mathbf{791.5\text{ TFLOP/s}}$$

(With boost clocks $\sim 1.98\text{ GHz}$, official peak dense FP16 reaches $989\text{ TFLOP/s}$, and with 2:4 structured sparsity reaches $1{,}978\text{ TFLOP/s}$).
