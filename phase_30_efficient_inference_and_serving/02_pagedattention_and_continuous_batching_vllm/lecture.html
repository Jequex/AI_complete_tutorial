Topic 30.2

PagedAttention & Continuous Batching (vLLM)

Iteration-level batch scheduling, virtual memory paging for KV caches, and zero-overhead Copy-on-Write parallel sampling.

1. The 12-Year-Old Intuition

Imagine running a 50-room hotel with two different booking managers:

  • Manager 1 (Static Batching): Demands that 10 guests arrive together and refuses to clean or re-assign any room until the last and slowest guest leaves. If 9 guests stay for 1 night and 1 stays for 7 nights, 9 rooms remain empty and locked for 6 whole days while travelers waiting in line are turned away.
  • Manager 2 (Continuous Batching): Operates by the minute. The instant a guest returns their room key, the room is cleaned and handed to the very next waiting traveler. Rooms are occupied 100% of the time.

Now consider how they handle luggage storage:

  • Traditional Contiguous Buffers: Reserves a giant 50-suitcase closet for every guest, even if they only carry a backpack. 70% of storage space sits empty, yet new luggage is rejected because the hotel is "out of room."
  • PagedAttention: Uses small 16-shirt storage lockers. You get 1 locker on arrival. When it fills, you get another locker down the hall. A directory (Block Table) tracks your lockers. Memory waste plummets from 80% to under 1%!

2. Mathematical Symbol Decoder

Symbol Name Domain / Type Physical / System Interpretation
$\mathcal{B}_{\text{size}}$ Block Size Integer (16 or 32) Number of tokens stored inside a single physical KV memory block.
$T_{\text{block}}$ Logical-to-Physical Table $\mathbb{N} \to \mathbb{N}$ Page table mapping logical sequence block indices to physical HBM block indices.
$\text{ref\_count}(i)$ Reference Count Integer $\ge 0$ Number of active sequences sharing physical block $i$ (enabling Copy-on-Write).
$\eta_{\text{mem}}$ Memory Utilization $[0.0, 1.0]$ Ratio of actively valid cached tokens over total physically allocated capacity.

3. The Architecture of PagedAttention

Inspired by Operating System virtual memory paging, PagedAttention breaks sequential KV allocations into fixed-size physical blocks:

Logical vs. Physical Memory Mapping

A sequence with 37 tokens with block size $\mathcal{B}_{\text{size}} = 16$ spans 3 logical blocks:

  • Logical Block 0 (Tokens 0..15) → Maps to Physical Block 42 (Full)
  • Logical Block 1 (Tokens 16..31) → Maps to Physical Block 109 (Full)
  • Logical Block 2 (Tokens 32..36) → Maps to Physical Block 17 (Contains 5 tokens, 11 free slots)

Physical blocks need not be contiguous in GPU memory. Hardware pointers are dispatched directly to the non-contiguous attention kernel.

4. Analytical Waste Derivation

For an average sequence length $\bar{L}$ with block size $\mathcal{B}_{\text{size}}$:

$$\mathbb{E}[\text{Wasted Memory}] = \frac{\mathcal{B}_{\text{size}} - 1}{2} \approx \frac{\mathcal{B}_{\text{size}}}{2} \quad \text{tokens}$$ $$\text{Memory Waste Ratio} = \frac{\mathcal{B}_{\text{size}}}{2 \cdot \bar{L}}$$

For $\bar{L} = 1024$ and $\mathcal{B}_{\text{size}} = 16$, the memory waste is only $\frac{8}{1024} = \mathbf{0.78\%}$, compared to $60\text{--}80\%$ in contiguous pre-allocation systems.

5. Copy-on-Write (CoW) Fork Mechanics

When sampling multiple completions for a prompt (e.g., beam search or best-of-N):

  • Prompt blocks are shared among all child branches with $\text{ref\_count} = K$. Zero additional KV memory is allocated.
  • When a child sequence writes a new token, if the current block is shared, the block manager duplicates only that single 16-token block and decrements $\text{ref\_count}$.
