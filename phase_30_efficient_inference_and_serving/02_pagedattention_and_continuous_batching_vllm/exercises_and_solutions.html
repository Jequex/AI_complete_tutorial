Exercise 1: Quantitative Analysis of Memory Fragmentation

A 40 GB KV memory pool serves requests with average context length $\bar{L} = 600$ tokens, but the model supports $S_{\text{max}} = 4096$ tokens. Each token consumes 320 KB.

  1. Compute memory waste and concurrent request capacity under contiguous pre-allocation.
  2. Compute memory waste and concurrent capacity under PagedAttention with $\mathcal{B}_{\text{size}} = 16$.
  3. Calculate the throughput capacity gain factor.
View Complete Step-by-Step Solution

1. Contiguous Pre-allocation

Allocated per sequence: $4096 \times 320 \text{ KB} = 1.31072 \text{ GB}$.

Used per sequence: $600 \times 320 \text{ KB} = 0.192 \text{ GB}$.

$$\text{Waste} = 1 - \frac{600}{4096} = \mathbf{85.35\%}$$ $$\text{Capacity} = \lfloor 40 / 1.31072 \rfloor = \mathbf{30 \text{ concurrent requests}}$$

2. PagedAttention ($\mathcal{B}_{\text{size}} = 16$)

$$\mathbb{E}[\text{Wasted Tokens}] = \frac{15}{2} = 7.5 \text{ tokens} \implies \text{Waste} = \frac{7.5}{600} = \mathbf{1.25\%}$$ $$\text{Allocated per sequence} \approx (600 + 7.5) \times 320 \text{ KB} \approx 0.1944 \text{ GB}$$ $$\text{Capacity} = \lfloor 40 / 0.1944 \rfloor = \mathbf{205 \text{ concurrent requests}}$$

3. Capacity Gain

$$\text{Gain Factor} = \frac{205}{30} \approx \mathbf{6.83\times}$$

Exercise 2: Copy-on-Write Physical Block Allocation Trace

A prompt of 35 tokens is submitted with parallel sampling $n=3$ using $\mathcal{B}_{\text{size}} = 16$. Trace physical block allocations and reference counts when Branch A generates 1 token and Branch B generates 15 tokens.

View Complete Step-by-Step Solution

1. Prompt Ingestion

Prompt requires $\lceil 35/16 \rceil = 3$ blocks: $P_1$ (tokens 0..15), $P_2$ (16..31), $P_3$ (32..34, partial). All three branches ($A, B, C$) point to $[P_1, P_2, P_3]$ with $\text{ref\_count} = 3$. Memory overhead is zero bytes.

2. Branch A Generates 1 Token

Block $P_3$ has $\text{ref\_count} = 3 > 1$. Copy-on-Write triggers: a new block $P_4$ is allocated, tokens 32..34 are copied, token 35 is appended. $\text{ref\_count}(P_3)$ decrements to 2; $\text{ref\_count}(P_4) = 1$.

3. Branch B Generates 15 Tokens

Branch B copies tokens 32..34 into new block $P_5$, filling it with 13 tokens (48 total). Its remaining 2 tokens allocate a new physical block $P_6$. Final block table for Branch B: $[P_1, P_2, P_5, P_6]$.

Exercise 3: Throughput Comparison: Static vs. Continuous Batching

Compare execution time for 8 requests (4 running, 4 queued) whose generation lengths vary from 20 to 200 tokens under static batching vs. continuous iteration-level scheduling.

View Complete Step-by-Step Solution

Static Batching: Waits for the longest sequence (200 tokens) in Batch 1 before starting Batch 2: $2 \times (20 \text{ ms} + 200 \times 10 \text{ ms}) = \mathbf{4040 \text{ ms}}$.

Continuous Batching: As soon as a sequence completes at step 20, 40, or 60, a queued request immediately takes its place. Total time drops to $\approx \mathbf{2400 \text{ ms}}$ (a $\mathbf{1.68\times}$ speedup with zero idle slot waste).
