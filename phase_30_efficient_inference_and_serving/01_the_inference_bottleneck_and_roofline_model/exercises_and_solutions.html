Exercise 1: Roofline Analysis of Prefill vs. Decode on NVIDIA H100

An inference engine serves a 13B parameter dense Transformer in FP16 ($M_{\text{weights}} = 26 \text{ GB}$) on an NVIDIA H100 SXM5 GPU ($P_{\text{peak}} = 989 \text{ TFLOP/s}$, $B_{\text{mem}} = 3.35 \text{ TB/s}$).

  1. Calculate the ridge point $I^* = P_{\text{peak}} / B_{\text{mem}}$.
  2. For a single prefill request of $S = 2048$ tokens ($b = 1$), compute operational intensity $I_{\text{prefill}}$, attainable performance $P$, and latency. Classify whether it is memory-bound or compute-bound.
  3. For decode with $b = 1$, compute operational intensity $I_{\text{decode}}$, attainable performance $P$, time per token, and GPU compute utilization.
View Complete Step-by-Step Solution

1. Ridge Point Calculation

$$I^* = \frac{989 \times 10^{12} \text{ FLOP/s}}{3.35 \times 10^{12} \text{ Bytes/s}} \approx \mathbf{295.22 \text{ FLOPs/Byte}}$$

2. Prefill Phase ($b = 1, S = 2048$)

Total compute: $2 \times (13 \times 10^9) \times 2048 = 53.248 \text{ TFLOPs}$.

Memory streamed: $26 \text{ GB}$.

$$I_{\text{prefill}} = \frac{53.248 \times 10^{12} \text{ FLOPs}}{26 \times 10^9 \text{ Bytes}} = \mathbf{2048 \text{ FLOPs/Byte}}$$

Since $I_{\text{prefill}} = 2048 > I^* = 295.22$, prefill is Compute-Bound.

Attainable speed $P = P_{\text{peak}} = 989 \text{ TFLOP/s}$. Latency $T_{\text{prefill}} = 53.248 / 989 \approx \mathbf{53.8 \text{ ms}}$.

3. Decode Phase ($b = 1, s = 1$)

Total compute: $2 \times (13 \times 10^9) \times 1 = 0.026 \text{ TFLOPs}$.

Memory streamed: $26 \text{ GB}$ (the weights must be loaded to generate 1 token!).

$$I_{\text{decode}} = \frac{0.026 \times 10^{12} \text{ FLOPs}}{26 \times 10^9 \text{ Bytes}} = \mathbf{1.0 \text{ FLOP/Byte}}$$

Since $I_{\text{decode}} = 1.0 \ll I^*$, decode is Memory-Bandwidth Bound.

Attainable speed $P = B_{\text{mem}} \cdot I = 3.35 \text{ TFLOP/s}$.

Time per token $T_{\text{decode}} = 26 \text{ GB} / 3.35 \text{ TB/s} \approx \mathbf{7.76 \text{ ms}}$ ($128.8 \text{ tokens/sec}$).

GPU Tensor Core Utilization: $\frac{3.35}{989} \approx \mathbf{0.339\%}$. Over $99.6\%$ of hardware compute is idle!

Exercise 2: KV Cache Memory Scaling and Max Concurrent Batch Capacity

Consider LLaMA-2-70B ($n_{\text{layers}} = 80, n_{\text{heads}} = 64, d_{\text{head}} = 128$) served in FP16 ($e = 2$ bytes).

  1. Compute the memory per token under Grouped-Query Attention ($n_{\text{kv\_heads}} = 8$) versus Multi-Head Attention ($n_{\text{kv\_heads}} = 64$).
  2. On an 8-GPU cluster with 640 GB total VRAM, model weights take 140 GB, and system overhead takes 40 GB. For an average sequence length of $s = 4096$, compute the maximum concurrent batch size $b_{\text{max}}$ under GQA.
View Complete Step-by-Step Solution

1. KV Memory per Token

$$\text{Bytes/token (GQA)} = 4 \cdot n_{\text{layers}} \cdot n_{\text{kv\_heads}} \cdot d_{\text{head}} = 4 \times 80 \times 8 \times 128 = \mathbf{327,680 \text{ Bytes}} = \mathbf{320 \text{ KB}}$$ $$\text{Bytes/token (MHA)} = 4 \times 80 \times 64 \times 128 = \mathbf{2,621,440 \text{ Bytes}} = \mathbf{2560 \text{ KB}} = \mathbf{2.5 \text{ MB}}$$

GQA provides an exact $\frac{64}{8} = \mathbf{8.0\times}$ memory reduction.

2. Maximum Batch Size $b_{\text{max}}$

Available memory for KV cache: $640 - 140 - 40 = \mathbf{460 \text{ GB}}$.

Per-sequence memory at $s = 4096$: $327,680 \times 4096 = 1,342,177,280 \text{ Bytes} \approx \mathbf{1.342 \text{ GB}}$.

$$b_{\text{max}} = \left\lfloor \frac{460 \times 10^9}{1,342,177,280} \right\rfloor = \mathbf{342 \text{ concurrent sequences}}$$

Under MHA, each sequence would take $10.74 \text{ GB}$, capping capacity at only 42 sequences.

Exercise 3: Analytical Derivation of the Critical Compute-Saturation Batch Size

Prove that the minimal batch size $b^*$ required to transition an LLM decode phase from memory-bound to compute-bound on modern accelerators is approximately $b^* \approx P_{\text{peak}} / B_{\text{mem}}$.

View Complete Step-by-Step Solution

At each decode step for batch size $b$, FLOPs are $2 \cdot b \cdot N_{\text{params}}$.

Memory loaded is dominated by weights $e \cdot N_{\text{params}}$ (when context length is moderate):

$$I(b) = \frac{\text{FLOPs}}{\text{Bytes}} \approx \frac{2 \cdot b \cdot N_{\text{params}}}{e \cdot N_{\text{params}}} = \frac{2 \cdot b}{e}$$

For FP16 ($e = 2$ bytes), $I(b) \approx b \text{ FLOPs/Byte}$.

To enter the compute-bound regime, operational intensity must exceed the ridge point:

$$I(b) \ge I^* \iff b \ge \frac{P_{\text{peak}}}{B_{\text{mem}}}$$ $$\boxed{b^* \approx \frac{P_{\text{peak}}}{B_{\text{mem}}}}$$

For an H100 GPU, $b^* \approx 295$. Interactive systems rarely achieve this batch size due to tail latency SLA constraints and Poisson arrival variance.
