Exercise 1: Quantitative KV Scaling Across MHA, GQA, MQA & Tensor Parallelism

For a 70B parameter model ($n_{\text{layers}} = 80, H = 64, d_{\text{head}} = 128$) at batch size 32 and context length 8192:

  1. Compute total KV memory under MHA, GQA ($H_{\text{kv}} = 8$), and MQA ($H_{\text{kv}} = 1$).
  2. Compute per-GPU memory when served across an 8-GPU Tensor Parallel cluster ($N_{\text{tp}} = 8$).
View Complete Step-by-Step Solution

1. Total KV Cache Footprint

$\text{Mem}_{\text{KV}} = 4 \cdot 80 \cdot H_{\text{kv}} \cdot 128 \cdot 32 \cdot 8192$ bytes:

  • MHA ($H_{\text{kv}} = 64$): $\mathbf{687.19 \text{ GB}}$
  • GQA ($H_{\text{kv}} = 8$): $\mathbf{85.90 \text{ GB}}$ ($8\times$ reduction)
  • MQA ($H_{\text{kv}} = 1$): $\mathbf{10.74 \text{ GB}}$ ($64\times$ reduction)

2. Per-GPU Sharded Footprint ($N_{\text{tp}} = 8$)

  • MHA: $687.19 / 8 = \mathbf{85.90 \text{ GB/GPU}}$ (exceeds an 80GB GPU)
  • GQA: $85.90 / 8 = \mathbf{10.74 \text{ GB/GPU}}$ (easily fits alongside weights)
  • MQA: $\mathbf{10.74 \text{ GB/GPU}}$ (replicated across ranks)

Exercise 2: Heavy Hitter Oracle (H2O) Dynamic Eviction Trace

Trace step-by-step attention weight accumulation and identify the evicted token when cache budget is limited to 6 tokens ($W_{\text{sink}} = 2, W_{\text{recency}} = 2, k_{\text{heavy}} = 2$).

View Complete Step-by-Step Solution

Initial state: Sinks `{1, 2}`, Candidates `{5, 6, 8}`, Recency `{10}`.

New arrival Token 11 brings total tokens to 7. Candidate cumulative scores:

  • Token 8: $5.7 + 0.15 = 5.85$ (Heavy Hitter 1)
  • Token 5: $4.2 + 0.30 = 4.50$ (Heavy Hitter 2)
  • Token 6: $1.1 + 0.05 = \mathbf{1.15}$ (Lowest score outside protected windows → Evicted!)

Token 6 is discarded, restoring cache size to 6 tokens.

Exercise 3: Tensor Parallel Communication Overhead in Prefill vs. Decode

Compare All-Reduce network volume across 80 layers for prefill ($s = 2048$) vs decode ($s = 1$) at batch size 32 on 8 GPUs.

View Complete Step-by-Step Solution

Ring All-Reduce volume: $2 \cdot \frac{N_{\text{tp}}-1}{N_{\text{tp}}} \cdot (b \cdot s \cdot d \cdot e)$ across 160 collectives (2 per layer):

  • Prefill ($s = 2048$): Transmits $\mathbf{300.6 \text{ GB}}$ of activation data.
  • Decode ($s = 1$): Transmits only $\mathbf{143.36 \text{ MB}}$ of activation data.

In the decode phase, inter-GPU communication is trivial and completely hidden behind memory stalls.
