## 1. Executive Summary & The 12-Year-Old Analogy

Pre-training equips a language model with broad linguistic features and world knowledge, but it is **the quality, diversity, and formatting of the Instruction Dataset** that determines how effectively that intelligence is unlocked during conversation.

Modern instruction datasets are rarely hand-written one question at a time. Instead, dataset engineering employs algorithmic pipelines such as **Self-Instruct** (bootstrapping synthetic instructions using teacher models) and **Evol-Instruct** (systematically increasing difficulty and domain breadth).

Furthermore, real-world deployment requires modeling **multi-turn interactions** and **function calling (tool use)**. In multi-turn training, conversations with many back-and-forth exchanges are compiled into single contiguous token sequences where:
1. All system instructions, user queries, and external tool execution responses are **masked** (`target = -100`).
2. Only the assistant's generated thoughts, tool call queries, and final responses are **supervised**.

```text
[SYSTEM: Tools Available] (Masked -100)
       │
[USER: "Book flight to NYC"] (Masked -100)
       │
[ASSISTANT: <tool_call>search_flights("NYC")</tool_call>] (SUPERVISED)
       │
[TOOL_OUTPUT: "Flight 204: $199"] (Masked -100: Generated by API, not Model!)
       │
[ASSISTANT: "I found Flight 204 for $199. Shall I book it?"] (SUPERVISED)
```

### The 12-Year-Old Analogy: The Rehearsal Script for a Movie Actor

Imagine you are an actor rehearsing for a superhero movie:

The director hands you a full script:
- **Scene Setting:** `EXT. WAREHOUSE - RAINY NIGHT` *(Stage directions)*
- **Villain:** *"You are too late to stop the countdown!"*
- **Special Effects / Props:** `[Lightning flashes, alarm sounds]`
- **Your Line (Hero):** *"The countdown stops now!"*
- **Villain:** *"Never!"*
- **Special Effects / Props:** `[Computer console explodes]`
- **Your Line (Hero):** *"Stand down."*

When you sit at your desk to practice, you read the whole script so you know what is going on. But what do you practice speaking aloud?
- You **do not** practice saying *"EXT. WAREHOUSE - RAINY NIGHT"*.
- You **do not** practice making the alarm noises or simulating lightning.
- You **do not** memorize the Villain's lines to recite them yourself.

You memorize and practice **only your lines**, conditioned on hearing the villain speak and seeing the lightning flash!

In an AI conversation:
- The user and system are the other actors and director.
- The external API tools are the props and lightning flashes.
- The LLM is the actor. It reads the whole scene (context), but during rehearsal (SFT training), it is graded **only on its own lines**.

## 3. Instruction Dataset Engineering Paradigms

```
                       SEED TASKS (175 human examples)
                                     │
                 ┌───────────────────┴───────────────────┐
                 ▼                                       ▼
       [ SELF-INSTRUCT ]                         [ EVOL-INSTRUCT ]
     Task Generation Prompt                     Complexity Evolution
     Input / Output Synthesis                   - Add Constraints
     ROUGE-L Filter (< 0.7)                     - Deepen Reasoning
                 │                              - Concretize Inputs
                 ▼                                       │
     52,000 Synthetic Tasks                              ▼
     (Alpaca, Vicuna)                       Complex Multi-Step Reasoning
                                            (WizardLM, UltraChat)
```

### 3.1 Self-Instruct (Wang et al., 2022)
The Self-Instruct pipeline bootstraps a massive instruction dataset from a small initial collection of ~175 human-written seed tasks:

1. **Task Generation:** Sample 8 tasks from the existing pool (including seed tasks) as few-shot in-context demonstrations to prompt a teacher model (e.g., GPT-3/GPT-4) to generate new task instructions.
2. **Input Generation:** Classify whether the generated task is *input-free* (e.g., "Write an essay about photosynthesis") or *input-requiring* (e.g., "Summarize the following article: ..."). Generate input text accordingly.
3. **Output Synthesis:** Prompt the teacher model to write the complete, high-quality target completion $\mathbf{y}$.
4. **Deduplication & Quality Pruning:** Calculate the ROUGE-L similarity between the candidate instruction $s_{\text{new}}$ and all existing instructions in $\mathcal{D}$:
   $$\max_{s \in \mathcal{D}} \text{ROUGE-L}(s_{\text{new}}, s) < 0.70$$
   Discard instructions that are too similar, too short, or degenerate.

---

### 3.2 Evol-Instruct (WizardLM, Xu et al., 2023)
While Self-Instruct creates breadth, many generated instructions remain simple or shallow. **Evol-Instruct** uses an automated evolutionary prompt engine to deepen task complexity:

1. **In-Depth Evolution (Complicating the Task):**
   - **Add Constraints:** Inject explicit conditions (e.g., "Solve this in $\mathcal{O}(N \log N)$ time and without using extra memory").
   - **Deepen Reasoning:** Require multi-hop logical deductions ("Explain why this happened, identify three downstream consequences, and rank them").
   - **Concretizing:** Transform abstract concepts into real-world case studies.
2. **In-Breadth Evolution (Domain Mutation):**
   - Mutate the prompt into an entirely distinct, specialized subject area (e.g. quantum cryptography, marine biology).
3. **Elimination / Failure Filter:**
   - Discard generated prompts if the teacher model outputs a refusal or cannot generate a valid solution.

### 3.3 Large-Scale Multi-Turn Corpora: UltraChat & ShareGPT
- **UltraChat (Ding et al., 2023):** Systematically generated multi-turn dialogues where two LLMs converse across three themes: questions about the world, writing & creation, and assistance on problem-solving.
- **ShareGPT:** Organic human-LLM conversational logs containing multi-turn exchanges, debugging sessions, and iterative revisions.

## 4. Multi-Turn Conversation Modeling & Exact Masking

A conversation consists of $N$ alternating turns:
$$\mathcal{T} = [(\text{sys}, s), (\text{usr}, u_1), (\text{asst}, a_1), (\text{usr}, u_2), (\text{asst}, a_2), \dots]$$

### 4.1 Sequence Concatenation
The dialogue is rendered into a single contiguous token sequence:
$$\mathbf{w} = \tau_{\text{sys}} \circ \tau_{\text{usr}, 1} \circ \tau_{\text{asst}, 1} \circ \tau_{\text{usr}, 2} \circ \tau_{\text{asst}, 2}$$

### 4.2 The Multi-Turn Masking Rule
To prevent data contamination and preserve autoregressive causal context:
1. **Context Visibility:** The model's self-attention mask is lower-triangular causal ($M_{ij} = 0$ for $j \le i$), allowing assistant turn $a_2$ to attend to $u_1, a_1,$ and $u_2$.
2. **Loss Masking Rule:**
   $$\text{target}_t = \begin{cases} -100 & \text{if } w_t \in \text{sys} \lor w_t \in u_k \\ w_{t+1} & \text{if } w_t \in a_k \end{cases}$$
Notice that $u_1$ and $a_1$ are **not** discarded when training on $a_2$. The full conversational history serves as conditional context, but only assistant outputs contribute to parameter updates.

## 5. Tool Use & Function Calling Modeling

Modern LLMs act as autonomous agents by invoking external functions (calculators, web search, database lookups).

```
[System + Tools Schema] ──> [User Query] ──> [Assistant Generates Tool Call]
                                                           │
                                                           ▼ (Environment Executes)
[Assistant Final Answer] <── [Tool Response Injected] <────┘
```

### 5.1 The Function Calling Lifecycle
1. **Schema Injection:** The system prompt defines available tools via JSON schema:
   ```json
   {
     "name": "get_weather",
     "description": "Fetch current temperature",
     "parameters": {"properties": {"city": {"type": "string"}}}
   }
   ```
2. **Model Call Generation:** The model predicts a structured call tag:
   ```text
   <tool_call>{"name": "get_weather", "arguments": {"city": "Tokyo"}}</tool_call>
   ```
   **This generation IS supervised** (target = token IDs), teaching the model schema compliance and argument extraction.
3. **Execution & Injection:** The host runtime catches the tool call, invokes the real API, and appends the result into the context:
   ```text
   <tool_response>{"temp_c": 22, "condition": "Cloudy"}</tool_response>
   ```
   **Crucial Rule:** The tool response **MUST BE MASKED** (`target = -100`). The model did not generate the weather data, and penalizing the model for failing to guess real-time weather readings destroys calibration.
4. **Final Synthesis:** The assistant generates its final conversational answer:
   ```text
   The current weather in Tokyo is 22°C and cloudy.
   ```
   **This generation IS supervised.**

## 6. Sequence Packing Mechanics

During training on GPU clusters, padding sequences to a fixed `max_seq_len` wastes up to 60% of compute on pad tokens (`<pad>`).

**Sequence Packing** concatenates multiple independent dialogues $\mathcal{D}_1, \mathcal{D}_2, \mathcal{D}_3$ into a single context window of length $T_{\max}$:
```text
Batch 1: [ --- Dialogue 1 --- ][ ------ Dialogue 2 ------ ][ - Dialogue 3 - ][PAD]
```
To avoid cross-dialogue attention contamination:
1. **Segment IDs:** Each dialogue receives an integer segment ID ($1, 2, 3$).
2. **Block-Diagonal Attention:** Attention mask entries $M_{ij} = -\infty$ whenever $\text{Segment}(i) \ne \text{Segment}(j)$, even if $j < i$.
