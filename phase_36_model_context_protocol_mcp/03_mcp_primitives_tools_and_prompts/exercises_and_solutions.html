Exercise 1: Protocol Errors vs. Tool Execution Failures

When does an MCP server return a JSON-RPC Error object versus a valid Result with isError: true?

Click to Reveal Solution & Explanation

Rule of Thumb:

  • JSON-RPC Error Object (e.g. -32700, -32601): Used when wire communication or RPC routing fails (syntax error, non-existent method).
  • Tool Result with isError: true: Used for all internal tool runtime failures (ZeroDivisionError, database query failure, schema argument validation failure). This allows the LLM to inspect the error string and self-correct without dropping the connection.

Exercise 2: JSON Schema Validation Edge Cases

Given an input schema requiring username and role (enum: viewer, editor, admin), what happens when an unexpected enum value like superadmin is passed?

Click to Reveal Solution & Explanation

Answer: The tool registry's JSON Schema validator catches the enum violation before executing the tool. It returns isError: true with a descriptive text error:

Validation Error: Field 'arguments.role' value 'superadmin' not in allowed enum: ['viewer', 'editor', 'admin']

Exercise 3: Multi-Turn Prompt Template Workflow

Why do MCP prompt templates return an array of messages rather than a single raw text string?

Click to Reveal Solution & Explanation

Answer: Real-world AI workflows frequently require few-shot guidance or multi-turn conversational bootstrapping. By returning an array of structured messages (with roles like user, assistant), an MCP server can prime the model with few-shot demonstrations, expert system personas, and multi-step diagnostic plans.
