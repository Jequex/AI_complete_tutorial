Topic 03: MCP Primitives — Tools & Prompts

JSON Schema parameter contracts, tool execution error segregation, and user-driven prompt templates.

1. The 12-Year-Old Intuitive Analogy: The Robot's Hands vs. Recipe Cards

In Topic 02, we gave the robot eyes to read books in the library (Resources). But reading a recipe doesn't bake the cake!

  • Tools (The Robot's Hands): Let the robot stir the pot and turn on the oven. But handing a robot hot tools requires a safety contract (JSON Schema). If the oven has an error, the robot reports back calmly rather than blowing up the kitchen.
  • Prompts (The Recipe Cards): Reusable instruction cards stored in a binder (e.g. /bake_cake). The user selects a card, fills in variables (flavor="vanilla"), and hands the plan to the assistant.

2. Complete Protocol Symbol Glossary

Symbol / Term Protocol Method / Field Description
$\text{tools/list}$ Catalog RPC Lists all available tools, their descriptions, and parameter JSON schemas.
$\text{tools/call}$ Invocation RPC Executes a tool with validated parameters. Returns content and isError.
$\text{isError}$ Boolean Field Set to true when execution or schema validation fails. Prevents protocol drop.
$\text{prompts/list}$ Catalog RPC Lists user-accessible prompt workflow templates and arguments.
$\text{prompts/get}$ Template Resolution RPC Injects arguments into template to construct multi-turn LLM messages.

4. The Crucial Difference: JSON-RPC Error vs. Tool isError

Core Architectural Law: A tool execution failure (e.g. database query syntax error, division by zero, invalid parameter) is returned inside result with "isError": true. It is NOT returned as a JSON-RPC -32603 error object. This allows the LLM to inspect the error message and adjust its reasoning without severing the transport session.
