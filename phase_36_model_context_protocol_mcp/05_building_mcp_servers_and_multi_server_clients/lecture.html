Topic 05: Building MCP Servers & Multi-Server Clients

End-to-end architecture: stdio server development, multi-server catalog aggregation, and agent decision loops.

1. The 12-Year-Old Intuitive Analogy: The Grand Symphony Conductor

Imagine conducting a world-class orchestra. The violinists hold the archived musical scores (Database Resource Server), the percussionists provide the powerful drum rolls (Compute Tool Server), and the singers harmonize on cue (Prompt Server).

The Host Orchestrator is the conductor. Before the performance, the conductor checks what instruments are present. During the symphony, the conductor points at specific sections at the right time, synthesizing their individual sounds into a masterpiece.

2. Complete Protocol Symbol Glossary

Symbol / Term Formal Concept Description
$\mathcal{S}_i$ Subprocess Server Instance Isolated child process exposing specialized tools or resources.
$\mathcal{O}_{\text{host}}$ Host Client Orchestrator Manager process holding the LLM loop and subprocess pipe handles.
$\Gamma_{\text{tools}}$ Unified Tool Catalog Combined tool manifest aggregated across all connected servers.
$\mathcal{R}_{\text{route}}$ Routing Table Hash map directing tool calls and resource URIs to their owning server.

4. Production Stdio Implementation Rules

  • Unbuffered I/O: Always flush stdout (sys.stdout.flush()) immediately after emitting each JSON line.
  • Stderr Isolation: Redirect all non-JSON debug logging to sys.stderr to prevent corrupting the host's parser.
  • Capability Guarding: Only query catalogs if the server advertised the corresponding capability during handshake.
  • Graceful Teardown: Send shutdown request, close pipes, wait with timeout, and escalate to SIGKILL if unresponsive.
