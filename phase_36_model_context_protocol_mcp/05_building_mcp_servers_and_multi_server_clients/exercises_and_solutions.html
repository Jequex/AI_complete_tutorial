Topic 05: Exercises & Solutions

Interactive exercises covering tool collision resolution, unbuffered pipe deadlocks, and multi-server agent pipelines.

Exercise 1: Multi-Server Tool Name Collisions

When multiple connected MCP servers expose a tool with the identical name (e.g., search), how should a host client namespace them?

Click to Reveal Solution & Explanation

Answer: The host client prefixes tool names with the server's unique identifier when presenting tool schemas to the model (e.g. github__search, elastic__search). When the LLM emits a function call with the prefixed name, the host client strips the prefix and dispatches the raw tool call to the intended target server.

Exercise 2: Unbuffered Pipe Deadlocks in Subprocesses

Why does omitting sys.stdout.flush() cause child stdio MCP servers to hang during handshake?

Click to Reveal Solution & Explanation

Answer: Operating systems buffer standard I/O into 4KB/8KB chunks when connected to pipes. A short JSON-RPC response stays trapped in the process memory buffer and never enters the OS pipe, causing the host to block indefinitely on readline().

Running with python3 -u or calling sys.stdout.flush() forces immediate transmission.

Exercise 3: DevOps Multi-Server Orchestration Trajectory

How does an autonomous agent chain resource reads from a Jira server, code edits from a Git server, and test executions from a CI server?

Click to Reveal Solution & Explanation

Answer: The agent acts as a stateful ReAct loop: reading ticket requirements via resources/read on the Ticket Server, applying code changes and branching via tools/call on the Git Server, invoking test validation on the Test Server, and updating the ticket state on completion.
