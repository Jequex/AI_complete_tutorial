Exercise 1: Handshake State Machine Invariants

If an uninitialized MCP server receives tools/list as its first input, how must it respond and what state transitions occur?

Click to Reveal Solution & Explanation

Answer: The server rejects the call with code -32600 (Invalid Request) stating that the session is not initialized. No state change occurs (remains UNINITIALIZED).

The client must first complete the two-step handshake: send initialize, receive capabilities, and send notifications/initialized.

Exercise 2: SSE Stateless Routing via Session IDs

Why do MCP SSE implementations embed the session ID into the POST message URL (e.g. /messages?session_id=...)?

Click to Reveal Solution & Explanation

Answer: Standard HTTP POST requests are stateless. By embedding the session_id in the target URL, the web server can immediately dispatch the incoming JSON-RPC payload to the exact in-memory state machine and push responses back through that specific client's open SSE stream.

Exercise 3: Asynchronous Execution vs. Heartbeat Timeouts

Why must long-running computations (e.g., 5-minute database backups) not block the server's main RPC thread?

Click to Reveal Solution & Explanation

Answer: If the worker blocks synchronously, it cannot respond to incoming ping heartbeats or cancellation signals. The host client will conclude the server has hung or deadlocked, terminating the subprocess. Work must run asynchronously, periodically emitting notifications/progress.
