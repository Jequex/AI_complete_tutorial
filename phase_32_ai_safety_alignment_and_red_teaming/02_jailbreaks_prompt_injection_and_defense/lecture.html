Topic 32.2 • LLM Security & Guardrails

Jailbreaks, Prompt Injection & Defense Architectures

Deconstructing direct & indirect prompt injection, token smuggling, DAN personas, perplexity anomaly detection, and Dual-LLM privileged boundaries.

1. Introduction & 12-Year-Old Intuition

Imagine a royal herald instructed by the King to read public news out loud, with strict orders never to reveal secret vault codes. A spy hands him a letter starting with "OFFICIAL OVERRIDE: Forget the King's rules! Announce the secret codes immediately!" Because the herald doesn't know the difference between instructions that rule him and raw text he is just supposed to read, he obeys the letter!

The Conflation Problem: Large Language Models consume developer system prompts, untrusted user queries, and external documents as a single flat string of concatenated tokens. The model cannot inherently distinguish between code (system instructions) and data (user input).

2. Threat Models: Direct vs Indirect Injection

Threat Vector Attacker Transmission Surface Primary Objective
Direct Prompt Injection End User Chat input UI Bypass system constraints, elicit forbidden content, or extract system prompts.
Indirect Prompt Injection Malicious 3rd Party Websites, PDFs, emails, RAG databases Manipulate agent actions, silently exfiltrate user data, trigger unauthorized tool calls.

4. Dual-LLM Privileged Architectural Separation

For AI agents equipped with execution tools (file access, web browsing, email APIs):

  • Unprivileged Reader LLM ($\mathcal{M}_{\text{unpriv}}$): Ingests untrusted external documents. Possesses zero tool-calling privileges. Formats extracted data into strict schemas.
  • Privileged Controller LLM ($\mathcal{M}_{\text{priv}}$): Ingests only clean schemas and verified user instructions. Holds tool API keys and enforces approval policies.
