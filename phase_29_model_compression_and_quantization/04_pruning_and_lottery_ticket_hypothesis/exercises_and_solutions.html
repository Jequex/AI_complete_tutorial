Exercise 1: Combinatorics & Metadata Encoding of NVIDIA 2:4 Semi-Structured Sparsity

Problem: In NVIDIA 2:4 sparsity, exactly 2 out of every 4 consecutive weights are non-zero.

  1. Compute the total number of distinct allowable non-zero configurations in a 4-element block.
  2. Show how local 2-bit column indexing encodes the non-zero positions.
  3. For a $1024 \times 1024$ FP16 matrix, compute total memory including metadata vs full dense storage.
View Complete Solution

1. Combinatorics: $\binom{4}{2} = \frac{4!}{2! 2!} = 6$ possible configurations.

2. Encoding: Each of the 2 non-zero entries requires $\log_2(4) = 2$ bits to identify its position within the 4-element window. Thus, $2 \times 2 = 4$ bits of metadata per block (0.5 bytes).

3. Storage on $1024 \times 1024$ FP16:

  • Dense: $1024 \times 1024 \times 2 \text{ bytes} = 2.00 \text{ MB}$.
  • 2:4 Sparse Weights: $524,288 \times 2 \text{ bytes} = 1.00 \text{ MB}$.
  • 2:4 Metadata: $262,144 \text{ blocks} \times 0.5 \text{ bytes} = 0.125 \text{ MB}$.
  • Total: $1.125 \text{ MB}$ ($1.78\times$ compression with $2\times$ Tensor Core speedup!).

Exercise 2: Derivation of the Iterative Magnitude Pruning (IMP) Rate

Problem: Derive the per-round pruning rate $p$ required to achieve final sparsity $S_{\text{final}}$ in $R$ rounds. Compute $p$ for $S_{\text{final}} = 0.85$ and $R = 8$.

View Complete Solution

The surviving fraction after $R$ rounds is $s_R = (1 - p)^R = 1 - S_{\text{final}}$.

$$\boxed{p = 1 - (1 - S_{\text{final}})^{1 / R}}$$

For $S_{\text{final}} = 0.85$ and $R = 8$:

$$p = 1 - (0.15)^{1/8} = 1 - 0.78917 = \mathbf{21.08\%}$$

Pruning $21.1\%$ of active weights per round smoothly reaches $85\%$ sparsity without network shock.

Exercise 3: Structured vs. Unstructured FLOP Reduction Analysis

Problem: Contrast FLOP execution on a $K \times N$ dense layer under 50% unstructured pruning vs 50% structured column pruning.

View Complete Solution

Unstructured: Standard dense GPU matrix engines (`GEMM`) load the full matrix from memory and multiply by zeros ($x_k \times 0.0 + \text{acc}$). All $2KN$ FLOPs and full memory traffic remain identical, providing 0% actual speedup.

Structured: Cutting $N$ down to $N/2$ columns physically reshapes the matrix into $\mathbf{W}' \in \mathbb{R}^{K \times (N/2)}$. Required FLOPs drop from $2KN$ to $KN$—an immediate, guaranteed $2.0\times$ speedup on any hardware.
